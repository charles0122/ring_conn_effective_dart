# 团队规范：风格候选规则评审

这份评审表用于团队会议前后统一讨论 `saropa_lints` 的风格规则取舍。
规则名称与上游 lint id 保持一致，便于直接映射到 `analysis_options.yaml`。

上游来源：[saropa_lints / README_STYLISTIC.md](https://github.com/saropa/saropa_lints/blob/main/README_STYLISTIC.md)

配套 CSV：[下载候选规则评审表](/assets/stylistic-rule-review.csv)

最近一次同步日期：`2026-05-27`

## 使用建议

1. 会前先顺着本页逐条预读，在每条规则的 `评审记录模板` 里记录自己的倾向。
2. 会议中优先讨论下面的“二选一冲突规则”，这些规则必须成对取舍。
3. 对 `低成本候选` 可以优先试运行，再决定是否升级为团队正式规范。
4. 对 `项目/业务相关` 或 `版本前提` 的规则，先确认适用范围，再决定是否纳入团队规范。

## 初筛分组说明

- `二选一`：存在明确对立规则，需要在会议里成对决策。
- `低成本候选`：可自动修复或迁移成本较低，适合先试运行。
- `通用候选`：没有明显对立项，也不强依赖具体业务，适合先异步预投票。
- `项目/业务相关`：更像团队或业务约束，不建议脱离项目上下文直接采纳。
- `版本前提`：依赖 Flutter 或 SDK 版本，需要先确认技术前提。
