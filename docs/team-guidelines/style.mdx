# 团队规范：代码风格

本页记录团队已经采纳的代码风格规则。它们优先于官方参考页中的原文表述。

### <span style={{ display: "inline-block", padding: "0.18rem 0.58rem", marginRight: "0.45rem", borderRadius: "999px", border: "1px solid rgba(21, 128, 61, 0.24)", background: "rgba(34, 197, 94, 0.16)", color: "#15803d", fontWeight: 800, fontSize: "0.78em", letterSpacing: "0.04em", lineHeight: 1.2, verticalAlign: "middle" }}>必须</span> 使用 `dart format` 格式化代码

规则描述：提交前应保持代码符合 `dart format` 的默认输出，不手工对抗格式化器。

采纳理由：统一的格式规则可以显著降低 review 噪音，也能避免团队成员在缩进、换行和括号布局上反复争论。

官方来源：[官方参考：使用 `dart format` 格式化代码](/effective-dart/style#do-format-your-code-using-dart-format)

相关 lints：无，依赖格式化工具本身。

### <span style={{ display: "inline-block", padding: "0.18rem 0.58rem", marginRight: "0.45rem", borderRadius: "999px", border: "1px solid rgba(185, 28, 28, 0.24)", background: "rgba(239, 68, 68, 0.16)", color: "#b91c1c", fontWeight: 800, fontSize: "0.78em", letterSpacing: "0.04em", lineHeight: 1.2, verticalAlign: "middle" }}>禁止</span> 使用前缀字母为变量或成员命名

规则描述：不要使用 `mName`、`sName`、`kDefaultTimeout` 这类靠前缀表达语义的命名方式。

采纳理由：Dart 的类型系统和上下文已经足够表达绝大多数语义，前缀会增加理解负担，也和现有 Flutter / Dart 生态习惯不一致。

官方来源：[官方参考：不要使用前缀字母](/effective-dart/style#dont-use-prefix-letters)

相关 lints：无，主要依赖 review 执行。

### <span style={{ display: "inline-block", padding: "0.18rem 0.58rem", marginRight: "0.45rem", borderRadius: "999px", border: "1px solid rgba(29, 78, 216, 0.24)", background: "rgba(59, 130, 246, 0.16)", color: "#1d4ed8", fontWeight: 800, fontSize: "0.78em", letterSpacing: "0.04em", lineHeight: 1.2, verticalAlign: "middle" }}>推荐</span> 常量使用 `lowerCamelCase`

规则描述：新增常量、静态常量以及枚举值时，优先使用 `lowerCamelCase`，不要继续引入 `SCREAMING_CAPS` 风格。

采纳理由：它与 Dart 生态的主流写法一致，也能减少常量与类型名、普通变量名之间的视觉割裂。

官方来源：[官方参考：推荐常量使用 `lowerCamelCase`](/effective-dart/style#prefer-using-lowercamelcase-for-constant-names)

相关 lints：`constant_identifier_names`
